# 스킬·에이전트 결정성 원칙 (스크립트 우선)

새 스킬(`skills/*/SKILL.md`)이나 에이전트(`agents/*.md`)를 만들거나 고칠 때, 그 절차에 담긴 각 단계가 **LLM 판단이 필요한 작업인지 아닌지**를 먼저 구분한다. 판단이 필요 없는 작업을 프롬프트 지시문(자연어)으로 기술하지 않는다.

이 파일은 advisory 컨텍스트다. 이 rule의 역할은 구현 시점에 Claude 스스로 "이걸 프롬프트로 시킬지, 스크립트로 뺄지"를 판단하도록 유도하는 것이다.

## 판단 기준

**결정적 작업** — 같은 입력이면 항상 같은 출력이 나오는 것. 예:

- 날짜·타임스탬프 비교 (예: `last_run` 이후 발행분만 필터)
- 중복 제거 (예: `url` 기준 dedup)
- 카운터 증감·리셋 (예: `consecutive_failures`, `alerted`)
- JSON 파일 읽기·병합·쓰기
- 정렬
- 파일명 슬러그 생성, 고정 포맷 문자열 조립

**LLM 판단이 실제로 필요한 작업** — 예:

- 자연어 이해·해석, 사용자 의도 파악
- 대화형 인터뷰 질문 생성 (다음 질문이 맥락에 따라 달라짐)
- 우선순위·뉘앙스 판단, 콘텐츠 품질 평가
- 회상 인터뷰 교정, Q&A 답변 작성처럼 원문 이해가 전제되는 응답 생성

## 판단 후 조치

- **결정적 작업** → `scripts/`에 스크립트로 구현하고, SKILL.md/agent.md에는 그 스크립트를 Bash로 호출·결과 해석만 지시로 남긴다. 언어는 프로젝트 컨벤션을 따른다(현재 이 저장소는 Python 3 표준 라이브러리만 사용 — README 참고).
- **판단이 필요한 작업** → 스크립트를 강제하지 않는다. 아래 "설명 의무"를 따른다.

## 스크립트 대신 판단에 맡겼다면 — 설명 의무

LLM 판단에 맡기기로 했다면 **구현을 마친 뒤 반드시 그 이유를 사용자에게 보고한다.**

**스킬·에이전트 파일 본문에는 남기지 않는다.**

이유 없이 "일단 프롬프트로 기술하고 넘어가지" 않는다.
