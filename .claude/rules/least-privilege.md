# 스킬·에이전트 권한 최소화 원칙

새 스킬(`skills/*/SKILL.md`)이나 에이전트(`agents/*.md`)를 만들거나 고칠 때, 기본값은 **닫힌 권한**이다. "일단 넉넉하게 주고 나중에 줄이기"가 아니라, 그 컴포넌트의 절차를 실행하는 데 실제로 필요한 도구만
하나씩 추가한다.

이 파일은 advisory 컨텍스트다. 이 rule의 역할은 구현 시점에 Claude 스스로 권한을 좁게 설계하도록 유도하는 것이다.

## 컴포넌트별 지침

### 에이전트 (`agents/*.md`)

- `tools:` 프론트매터를 항상 명시한다. 생략하면 전체 도구를 상속받으므로 절대 생략하지 않는다.
- 나열하는 도구는 본문 절차에서 실제로 호출하는 것만. "혹시 필요할까봐" 추가하지 않는다.
- 예: 웹 조사만 하는 에이전트는 `["WebSearch","WebFetch"]`만, 로컬 파일 집계만 하는 에이전트는 `["Read","Glob","Bash"]`만.

### 스킬 (`skills/*/SKILL.md`)

- SKILL.md의 `allowed-tools`는 강제되지 않는다 — 안전장치로 쓰지 말고, 문서화 목적으로만 쓴다.
- Bash 실행·파일 쓰기·외부 fetch처럼 위험도가 있는 작업은 가능하면 스킬이 메인 스레드에서 직접 하지 말고 **위임**한다. 위임처는 그 작업에 LLM 판단이 필요한지로 가른다:
  - **판단이 필요하면** → `tools:`가 좁게 제한된 서브에이전트 (예: 웹 조사는 qa-research가 전담, 스킬은 결과만 받는다).
  - **판단이 필요 없으면** → 전용 스크립트. **이쪽이 경계가 더 좁다** — `tools: ["Bash"]`인 서브에이전트는 아무 명령이나 실행할 수 있지만, 전용 스크립트 프로세스는 그 스크립트가 하는 일밖에 못 한다. 기계적인 작업을 서브에이전트로 감싸면 격리는 약해지고 왕복만 늘어난다.
- **헤드리스/무인 진입점** (OS 스케줄러가 `claude -p '/plugin:skill ...'`로 호출하는 스킬 — 예: `collect`): 그 호출 커맨드의 `--allowedTools`를 해당 스킬이 실제로 쓰는 도구·Bash 패턴으로 정확히 좁힌다. `Read,Write,Edit,Bash,Glob,Grep,Task,WebFetch,WebSearch` 같은 포괄 목록을 기본값으로 쓰지 않는다.

## 더 넓은 권한이 필요했다면 — 설명 의무

위 원칙보다 넓게 권한을 열어야 하는 경우가 실제로 있을 수 있다 (예: 위임이 대화 흐름을 깨서 스킬이 직접 처리해야 하는 경우, 여러 경로에 걸친 쓰기가 절차상 불가피한 경우 등). 그런 판단을 내렸다면 **구현을 마친 뒤 반드시 그 이유를 사용자에게 보고한다.**

**스킬·에이전트 파일 본문에는 남기지 않는다.**

이유 없이 넓은 권한만 부여하고 넘어가지 않는다.
