- `ROOT`: !`git rev-parse --show-toplevel 2>/dev/null || pwd`

아래 스크립트를 실행하고 출력된 절대 경로를 `SOLUTION_DIR`로 쓴다. 종료 코드가 0이 아니면 오류를 알리고 중단한다.

```bash
python3 "${CLAUDE_PLUGIN_ROOT}/scripts/solution_dir.py" "<ROOT>"
```

## 1. 대상 특정

`target`이 URL이나 slug면 거기서 slug를 뽑는다. `https://leetcode.com/problems/<slug>/` 뒤에 무엇이 붙어 있어도 `problems/` 다음 한 마디가 slug다.

`target`이 숫자면 `SOLUTION_DIR/*/<숫자>_*.*`를 Glob한다. 이 때, slug는 파일명의 `{id}_{slug}.{ext}`에서 읽는다. 파일이 여럿이면 (같은 문제를 여러 언어로 푼 경우) slug는 동일하니 한 파일만 확인한다.

`target`이 없으면 대화 맥락에서 방금 다룬 문제를 쓴다. 맥락에도 없으면 어느 문제인지 묻고 중단한다.

숫자로 찾았는데 파일이 없으면 문제 URL을 묻고 중단한다.

## 2. 현재 코드 확인

1단계에서 파일을 찾았다면 그 파일을 읽는다. 미마감 ANCHOR(`HH:MM`이 남아 있는 것) 아래 사용자가 쓴 코드가 어디까지 갔는지 확인하고, 이후 단계의 힌트와 질문을 그 지점에 맞춘다.

이미 사용자가 도달한 내용을 힌트로 반복하지 않는다.

## 3. 힌트 확보와 분기

대화 맥락에 `/leetlog:prep`이 받아온 `hints` 배열이 있으면 그것을 쓴다. 몇 번째까지 줬는지도 맥락에서 읽는다.

맥락에 없을 때만 아래 스크립트를 한 번 실행하고 출력의 `hints`를 쓴다. **실패해도 재시도하지 않는다.**

```bash
python3 "${CLAUDE_PLUGIN_ROOT}/scripts/fetch_question.py" "<slug>" --no-snippets
```

종료 코드가 0이 아니면 응답 자체를 받지 못한 것이다. 응답은 받았는데 `question`이 `null`이면 그 slug의 문제가 존재하지 않는 것이다. 대상이 틀렸으므로 문제 URL을 다시 묻고 중단한다.

아래 셋 중 하나의 경우 공식 힌트가 없는 것이다. 이 경우에는 4단계를 건너뛰고 **5단계 유도 질문 모드**로 간다.

- 재조회가 응답 자체를 받지 못했다
- `hints`가 빈 배열이다
- 맥락의 힌트를 이미 다 줬는데 사용자가 또 막혀 있다

셋 다 아니면 4단계로 간다.

## 4. 공식 힌트 제시

**한 번에 하나만 준다.** 다음 힌트가 남아 있으면 남았다는 사실을 알린다.

보여주기 전에 `<code>`, `<sup>`, `<b>` 같은 HTML 태그와 `&lt;`, `&nbsp;` 같은 엔티티를 제거한다.

## 5. 유도 질문 모드

아래 사다리를 **한 번에 한 단계씩** 올린다.

1. **관찰 유도** — 문제에서 주목할 패턴이나 제약을 질문으로 던진다. "입력이 10^5면 어떤 시간복잡도까지 허용될까요?"
2. **접근법** — 알고리즘 유형이나 자료구조 이름만 말한다. 구현 방법은 말하지 않는다.
3. **접근 방향** — 풀이 흐름을 단계로 설명한다. 코드는 쓰지 않는다.
4. **의사코드** — 로직 구조만 보여준다. 실제 문법으로 쓰지 않는다.

**마지막으로 준 공식 힌트가 도달한 단계보다 한 칸 위에서 시작한다.** 공식 힌트를 하나도 주지 않았으면 1단계부터 시작한다.

사용자의 접근이 틀렸다면 코드를 직접 고치지 않는다. 반례가 되는 입력을 제시해 스스로 발견하게 한다.

## 6. 정답 코드

**사용자가 명시적으로 요청한 경우에만 완성된 풀이를 준다.** 요청받지 않았으면 어느 단계에서도 쓰지 않는다.

줄 때도 대화에만 출력하고 풀이 파일에는 쓰지 않는다. 파일에 넣을지는 사용자가 정한다.
