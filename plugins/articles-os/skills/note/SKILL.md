## 권한 근거

본문 확보(세션 한정 지연 fetch)와 메모 저장(`save_note.py` 호출)을 메인 스레드에서 직접 수행한다 — 회상 인터뷰가 끝난 직후 같은 턴에서 저장 결과를 바로 알려줘야 하는 흐름이라 서브에이전트로 위임하면 왕복만 늘고 이득이 없다.

# 메모 (자유 덤프 → 회상 인터뷰 → .md)

목적은 "읽은 것을 머리와 메모에 잘 남기는 것"이다. 사용자가 직접 떠올려 말하게 한다 — 템플릿 채우기·플래시카드가 아니라 대화로 끌어낸다. 공통 규칙은 `${CLAUDE_PLUGIN_ROOT}/docs/conventions.md` 참조.

## 준비

1. `resolve_install.py` 규칙으로 활성 설치 결정, 아티클 특정 (번호/URL/제목).
2. 이 세션에서 이미 fetch했으면 재사용, 아니면 WebFetch(또는 실패 시 `curl -sL`)로 원문을 가져와 본문 텍스트만 추출해 확보한다(`articles.json`에 저장하지 않음 — 세션 한정. 인터뷰 질문 생성과 교정에 원문이 필요하다).
3. 해당 아티클의 `qa_log`를 읽는다 — **이미 Q&A에서 다룬 주제는 인터뷰에서 다시 묻지 않는다.**

## 1단계: 자유 덤프

**질문으로 시작하지 않는다.** 이렇게 연다: "이 아티클 읽고 든 생각·의문·좋았던 점·동의 안 되는 점, 뭐든 자유롭게 쏟아내 줘." 사용자가 먼저 말하게 하고, 끊지 않는다.

## 2단계: 비결정 인터뷰

고정 질문 세트 없음. 아티클 원문 + 덤프 + qa_log를 읽고 **그 자리에서** 질문을 만든다. 아티클을 지식형/인사이트형으로 미리 분류하지 않는다 — 한 아티클이 둘 다일 수 있다.

- **갭 채우기**: 덤프가 반응·의견에 쏠렸으면 개념을 짚는 질문으로, 사실·개념에 쏠렸으면 "그래서 어떻게 생각해?" 쪽으로 — **덜 건드린 쪽을 메운다.** 고정 비율이 아니다.
- **톤**: 채점·퀴즈가 아니라 "네 말로 다시 설명해봐" 식 대화. 암기 시험 금지 (예: "reflow 유발 CSS 속성 다 말해봐" 같은 것).
- **교정**: 사용자가 아티클 내용을 잘못 기억·이해하고 있으면 부드럽게 바로잡는다. 채점은 안 하되 틀린 기억을 굳히게 두지도 않는다.
- **길이**: 3~4턴을 상한 기준으로 삼되 자동 종료하지 않는다 — 도달하면 "더 파고들래, 아니면 여기서 정리할까?"를 묻는다. 계속 여부는 사용자가 쥔다.

## 3단계: .md 저장

형식은 conventions.md의 "메모 .md 형식" 참고. 본문을 아래 세 섹션으로 조립한다:

- **덤프**: 원문 그대로 보존 — 다듬지 않는다. 날것이 나중 회고에 쓸모 있다.
- **회상 인터뷰**: Q/A 형태로 사용자 발화 중심 기록.
- **정리**: 사용자가 덤프·인터뷰에서 한 말의 구조화. AI 재서술이 아니다 — 사용자의 단어·표현을 유지한다. 교정된 오해가 있으면 "처음엔 ~로 기억했는데 실제로는 ~" 형태로 남긴다.

조립한 본문을 stdin으로 넘겨 저장한다 — 슬러그 생성, `notes/YYYY-MM-DD-제목슬러그.md` 파일명 조립(중복 시 자동으로 `-2` 등 접미사), frontmatter 작성, `articles.json`의 `note_path` 갱신·`qa_log` 비우기(이력은 메모로 승격됐으므로)를 스크립트가 전담한다:

```bash
printf '%s' "<조립한 본문 markdown>" | python3 "${CLAUDE_PLUGIN_ROOT}/scripts/save_note.py" "<DATA>" "<아티클 url>" --title "<아티클 제목>" --source "<출처>"
```

`ok: false`면 원인(주로 아티클을 찾지 못함)을 확인하고 다시 시도한다.

저장 후 순서대로:

1. `python3 "${CLAUDE_PLUGIN_ROOT}/scripts/update_index.py" "<DATA>"` 실행 — index.md 자동 갱신.
2. 스크립트가 반환한 `note_path`를 사용자에게 알려주고 끝.
