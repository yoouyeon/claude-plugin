## 0. 데이터 경로 확인

`python3 "${CLAUDE_PLUGIN_ROOT}/scripts/paths.py" --require-initialized` 실행. 
`ok: false`면 `error`를 그대로 보여주고 끝낸다. 성공하면 `data_root`를 1단계에서 쓴다.

## 1. 대상 아티클 확정과 준비

1. 0단계 결과의 `data_root` 아래 `articles.json`에서 대상 아티클을 특정한다 (번호/URL/제목). 같은 아티클의 `qa_log`도 함께 읽어둔다 — **이미 Q&A에서 다룬 주제는 인터뷰에서 다시 묻지 않는다.**
2. 이 세션에서 이미 fetch했으면 재사용하고, 아니면 WebFetch(실패 시 `curl -sL`)로 원문을 가져와 본문 텍스트만 추출한다. 인터뷰 질문 생성과 교정에 원문이 필요하다. **`articles.json`에 저장하지 않는다.**

## 2. 자유 덤프

**질문으로 시작하지 않는다.** 
이렇게 연다: "이 아티클 읽고 든 생각·의문·좋았던 점·동의 안 되는 점, 뭐든 자유롭게 쏟아내 줘." 사용자가 먼저 말하게 하고, 끊지 않는다.

## 3. 회상 인터뷰

사용자가 직접 떠올려 말하게 한다 — 템플릿 채우기·플래시카드가 아니라 대화로 끌어낸다.

고정 질문 세트 없음. 아티클 원문 + 덤프 + `qa_log`를 읽고 **그 자리에서** 질문을 만든다. 아티클을 지식형/인사이트형으로 미리 분류하지 않는다.

- **갭 채우기**: 덤프가 반응·의견에 쏠렸으면 개념을 짚는 질문으로, 사실·개념에 쏠렸으면 "그래서 어떻게 생각해?" 쪽으로 — **덜 건드린 쪽을 메운다.** 고정 비율이 아니다.
- **톤**: 채점·퀴즈가 아니라 "네 말로 다시 설명해봐" 식 대화. 암기 시험 금지 (예: "reflow 유발 CSS 속성 다 말해봐" 같은 것).
- **교정**: 사용자가 아티클 내용을 잘못 기억·이해하고 있으면 부드럽게 바로잡는다. 채점은 안 하되 틀린 기억을 굳히게 두지도 않는다.
- **길이**: 3~4턴을 상한 기준으로 삼되 자동 종료하지 않는다 — 도달하면 "더 파고들래, 아니면 여기서 정리할까?"를 묻는다. 계속 여부는 사용자가 쥔다.

## 4. 메모 저장

본문을 아래 세 섹션으로 조립한다 (frontmatter·파일명은 `save_note.py`가 만든다):

- **덤프**: 원문 그대로 보존, 다듬지 않는다.
- **회상 인터뷰**: Q/A 형태로 사용자 발화 중심 기록.
- **정리**: 사용자가 덤프·인터뷰에서 한 말의 구조화. AI 재서술이 아니다 — 사용자의 단어·표현을 유지한다. 교정된 오해가 있으면 "처음엔 ~로 기억했는데 실제로는 ~" 형태로 남긴다.

조립한 본문을 stdin으로 넘겨 저장한다 — 슬러그 생성, `YYYY-MM-DD-제목슬러그.md` 파일명 조립(중복 시 자동으로 `-2` 등 접미사), frontmatter 작성, `articles.json`의 `note_path` 갱신·`qa_log` 비우기(이력은 메모로 승격됐으므로)를 스크립트가 전담한다:

```bash
python3 "${CLAUDE_PLUGIN_ROOT}/scripts/save_note.py" "<아티클 url>" --title "<아티클 제목>" --source "<출처>" <<'ARTICLES_OS_NOTE'
<조립한 본문 markdown>
ARTICLES_OS_NOTE
```

본문에는 따옴표·백틱·`$`가 섞여 들어오므로 위 heredoc 형식을 그대로 쓴다 — 셸이 본문을 해석하지 않는다.

`ok: false`면 `error`에 따라:

- `article not found for url: ...` : 1단계로 돌아가 URL 재확정 후 재시도
- `stdin body is empty` : 본문 다시 조립해 재시도
- 그 밖 : 재시도로 풀리지 않는다. `error`를 그대로 보여주고 중단

## 5. 마무리

1. 목차를 갱신한다.

   ```bash
   python3 "${CLAUDE_PLUGIN_ROOT}/scripts/update_index.py"
   ```

   이 명령이 실패해도 메모 자체는 이미 저장돼 있다 — 에러를 보여주되 저장 성공은 그대로 알린다.

2. `save_note.py`가 반환한 `full_path`(절대경로)를 사용자에게 알려주고 끝낸다.
