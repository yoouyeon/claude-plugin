# devdocs

스펙, 리서치 메모, PR 본문, 이슈 본문, README 같은 개발 문서를 한국어로 씁니다. 문서 종류에 맞는 문체로 쓰고, 다 쓴 뒤 줄표·번역투·종결어미 등을 검사합니다. 이미 있는 문서를 같은 기준으로 검사할 수도 있습니다.

## 시작하기

```
/plugin marketplace add yoouyeon/claude-plugin
/plugin install devdocs@yoouyeon-plugins
```

## 스킬 모음

| 스킬 | 사용 시점 |
|---|---|
| `/devdocs:write` | 문서를 새로 쓸 때 |
| `/devdocs:review` | 이미 있는 문서를 검사할 때 |

### 쓰기

```
/devdocs:write PR 본문
/devdocs:write 존댓말 스펙
```

문서 종류마다 기본 문체가 있고, "존댓말"이라고 하면 합니다체로 씁니다.

| 문서 | 기본 | 존댓말 |
|---|---|---|
| 스펙·설계 | -다체 | 합니다체 |
| 리서치 메모 | -다체 | 합니다체 |
| PR 본문 | 개조식 | 합니다체 |
| 이슈 본문 | 개조식 | 합니다체 |
| README | -다체 | 합니다체 |

본문은 먼저 작업 디렉토리의 `.devdocs/` 아래 임시 파일에 씁니다. 검사를 두 번 거친 뒤 PR·이슈 본문은 임시 파일 경로를 알려 주고, 나머지는 저장할 경로를 물어 그곳으로 옮깁니다. PR·이슈는 게시하지 않으므로 `gh pr create --body-file <경로>`로 직접 올릴 수 있습니다.

### 검사

```
/devdocs:review docs/specs/foo.md
```

걸린 곳을 번호 목록으로 보여 주고, 고른 번호만 고칩니다.

## 검사 항목

스크립트가 세는 항목입니다. 코드 블록과 인라인 코드는 세지 않습니다.

| 항목 | 허용치 |
|---|---|
| 줄표 | 0 |
| 이모지 | 0 |
| 금지어 | 0 |
| 번역투 조사 | 한 문단에 "~을 통해", "~에 대해", "~에 있어서"가 합쳐 3회 이상이면 걸림 |
| 종결어미 | 문서 문체와 맞지 않는 문장 끝 |

이 밖에 상투적 마무리, 묻지 않은 후속 제안, 근거 없는 평가어, "X가 아니라 Y" 대구 반복, 직역 은유, 강조가 아닌 용도로 쓴 볼드는 Claude가 읽고 판단합니다. 걸렸다고 모두 고치지는 않고, 이미 자연스러운 문장은 그대로 둡니다.
